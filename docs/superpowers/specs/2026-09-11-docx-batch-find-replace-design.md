# DocxReplace — 设计文档

日期：2026-09-11
状态：待用户审阅

## 1. 目标

一款 macOS 桌面应用，用于**批量查找并替换指定文件夹下所有 `.docx` 文件中的文字**，且**完全保持原有格式**。

典型场景：合同、标书、宣传材料里的公司名、产品名、日期批量改名，文档排版一个字都不能动。

## 2. 需求

| 项 | 结论 |
|---|---|
| 目标平台 | macOS（本机 macOS 26.5，Xcode 26.6 / Swift 6.3） |
| 输入范围 | 用户选择的文件夹，**递归所有子文件夹** |
| 文件类型 | **仅 `.docx`**。`.doc` 不处理，扫描时列出并提示「需先转为 .docx」 |
| 匹配方式 | 普通文字；提供「区分大小写」「全字匹配」两个开关（默认均关闭） |
| 覆盖部位 | 正文、表格、页眉、页脚、文本框/形状、脚注、尾注、批注 |
| 操作流程 | 先**扫描预览**（列出每个文件命中处数），确认后再执行替换 |
| 保存方式 | **原地修改**，修改前自动备份原文件 |
| 备份位置 | 优先 App 所在文件夹；不可写或位于 DerivedData 时退回 `~/Documents/DocxReplace备份/` |
| 分发 | 自己使用，Xcode 直接运行 / 导出本地 `.app`，不签名公证 |

## 3. 明确的能力边界（非目标）

1. **匹配不跨段落**。段落内任意位置均可（包括跨多个 run），但不跨段落标记。Word 中该行为需 `^p` 支持，极少使用。
2. **查找词与替换词都不能含换行符**，界面校验并拦截。
3. **不改动域代码**（`w:instrText`）。自动目录、页码等域的代码原样保留，仅其显示文本参与替换。
4. **不处理修订痕迹中被删除的文字**（`w:delText`）。
5. **替换文字的格式 = 命中处第一个字的格式**（与 Word 默认行为一致）。例：查找 `ABC`，`A` 为红色、`B` 为黑色，替换后新文字全部为红色。
6. **大小写不敏感模式下替换文字原样写入**，不做大小写推断。
7. 文档若带数字签名，修改后签名失效（Word 会提示），属预期现象。
8. 不处理 `.docm` / `.dotx` / `.rtf` / `.txt` 等其他格式。
9. 加密或有密码保护的文档无法读取，报告并跳过。
10. 「全字匹配」按 Unicode 字母/数字判定词边界，中文场景下会影响相邻汉字的匹配（与 Word 行为一致），默认关闭。

## 4. 技术选型

### 4.1 环境约束

**本机无法访问 GitHub**（实测连接超时），因此**禁止引入任何第三方依赖**（如 ZIPFoundation、XcodeGen）。方案必须完全基于系统能力实现。

可用系统能力（已验证）：

- `Compression` 框架：可直接在 Swift 中 `import`，其 `COMPRESSION_ZLIB` 产出的正是 ZIP 所需的 raw DEFLATE 流（RFC 1951），无需桥接头文件。
- `XMLDocument`（Foundation，macOS 专有）：完整 DOM 解析器。
- `textutil`、`unzip`（仅用于测试夹具生成与独立校验）。
- `zlib` 头文件与 `libz.tbd` 也在 SDK 内可用，但需要 Objective-C 桥接头，故不采用。

### 4.2 `.docx` 处理路线：自研保真引擎（方案 A）

不整体重写 XML，而是：

1. 用 `XMLDocument` **只做分析**——解析出段落结构、每个 `w:t` 的文字、以及它们在文档中的顺序。
2. 在纯文本层面计算替换（跨 run 匹配）。
3. 把改动**外科手术式地**应用回**原始 XML 字符串**——只替换目标 `w:t` 的文本内容，其余字节原封不动。

这样保证：

- 除被替换的文字外，XML 的其余部分**字节级不变**（属性顺序、命名空间、空白全部保留）。
- 性能远优于整文重序列化。
- 核心算法为纯函数，可完整单元测试。

### 4.3 为什么不选其他路线

- **整文 DOM 重写**：`XMLDocument` 序列化会改变属性顺序与空白，无法承诺「格式一个字节不变」。
- **Word 自动化（AppleScript）**：每个文件 1–3 秒，扫描预览就要逐个打开文件，与所选流程冲突；且需要自动化授权。仅对 `.doc` 有不可替代性，而 `.doc` 已确定不支持。

### 5.1 处理的 XML 部件

仅处理以下部件，其余部件（媒体、主题、设置、编号、字体表等）在重建 ZIP 时**原样直拷**：

| 部件 | 内容 |
|---|---|
| `word/document.xml` | 正文、表格、文本框/形状（`w:txbxContent` 嵌套在 document.xml 内） |
| `word/header*.xml` | 页眉 |
| `word/footer*.xml` | 页脚 |
| `word/footnotes.xml` | 脚注 |
| `word/endnotes.xml` | 尾注 |
| `word/comments.xml` | 批注 |

`word/glossary/document.xml`（自动图文集）不处理。

**前缀假设**：按 Word / WPS / Google Docs 导出的一致行为，`w:t`、`w:p` 等元素统一使用 `w:` 前缀。使用非 `w:` 前缀的文档不予支持（实际不会遇到）。

### 5.2 核心算法：跨 run 匹配与保格式替换

Word 会把一段连续文字拆成多个 run（拼写检查、格式变化、修订记录都会导致拆分），这是"明明有却搜不到"的根因。

**段落文字拼接**：对一个 `w:p`，按文档顺序收集其所有后代 `w:t` 的文本（**排除嵌套在其中的 `w:p`**——文本框会产生嵌套段落），拼成完整字符串 `S`，同时记录每个字符到 `(w:t 索引, 段内偏移)` 的映射。

**查找**：在 `S` 上按选项（区分大小写 / 全字匹配）查找所有不重叠命中。

**改写**（对每个命中 `[start, end)`）：

- 命中跨越 `w:t` 序列 `i..j`，以及各自的首尾偏移。
- `w:t[i]` 新文本 = 前缀 + **替换文本**
- `i < k < j` 的 `w:t[k]` 新文本 = 空
- `i == j` 时：`w:t[i]` = 前缀 + 替换文本 + 后缀；否则 `w:t[j]` = 后缀
- 未命中的 `w:t` **完全不动**

**格式归属**：替换文本写进 `w:t[i]`，因此继承第 `i` 个 run 的格式——对应边界第 5 条。

**写回原始 XML**：按 `w:t` 在文档中的出现序号定位到原始字符串中的对应片段，**从后往前**应用编辑（保证偏移不失效）。三处关键细节：

1. 若新文本首尾出现空白且原元素没有 `xml:space="preserve"`，需补上该属性——否则 Word 会吃掉空格。
2. 写回时按 XML 规则转义（`&` → `&amp;`、`<` → `&lt;`、`>` → `&gt;`）。
3. 定位 `w:t` 时需跳过 XML 注释与 CDATA 中的伪匹配。

### 5.3 ZIP 层

自研实现，基于系统 `Compression` 框架 + 自写 CRC32：

- **读**：解析 EOCD → 中央目录 → 各条目。支持 stored(0) 与 deflate(8)。压缩数据用 `compression_decode_buffer`（`COMPRESSION_ZLIB`，即 raw deflate）。尺寸取自中央目录（兼容带 data descriptor 的条目）。检测 zip64 并给出明确报错。
- **写**：**未修改的条目直接拷贝原始压缩字节**（不重新压缩，保证内容字节级一致）；被修改的部件用 `deflate` 重新压缩并更新 CRC32 与尺寸。重建中央目录与 EOCD。
- 若读取失败（损坏、加密），返回明确错误类型。

## 6. 数据流

### 6.1 扫描（只读）

```
选择文件夹
  → 递归遍历（并行，按 CPU 核数）
  → 识别 .docx / .doc / 其他（忽略）
  → 对每个 .docx：解压目标部件 → 计数命中处数
  → 结果列表：相对路径 + 命中数（0 命中灰显；错误标红；.doc 提示需转换）
```

`.docx` 扫描为只读操作，不写入任何文件。

### 6.2 替换

```
二次确认弹窗（将修改 N 个文件，共 M 处）
  → 建备份目录 <备份根>/DocxReplace备份_yyyy-MM-dd_HH-mm-ss/<源文件夹名>/
  → 串行逐文件处理（仅处理扫描时命中数 > 0 的文件；0 命中的文件完全不动）：
      1. 备份原文件（保留相对路径）——失败则跳过该文件，不替换；关闭备份时跳过本步
      2. 重新计算命中（以磁盘当前内容为准，防扫描后被改动）；此时 0 命中则记为「已无匹配」跳过
      3. 应用替换 → 写回（atomic 写入：写临时文件后替换）
      4. 记录结果
  → 完成报告：成功 N 文件 / M 处，跳过、失败原因，备份路径
  → 「打开备份文件夹」按钮
```

**备份根的定义**：App 包（`.app`）所在文件夹；若该位置不可写，或 App 位于 DerivedData 下（从 Xcode 直接运行的情形），则改用 `~/Documents/DocxReplace备份/`。实际使用的备份路径始终显示在界面上。

替换为**串行**执行（安全优先），支持中途取消；已完成的文件不回滚（有备份兜底）。

`.docx` 处理为纯本地解析，速度约几十毫秒/文件；整体耗时主要取决于备份的文件复制 IO。

**状态机**：空闲 → 扫描中（进度 + 取消）→ 已扫描 → 替换中（进度 + 当前文件 + 取消）→ 已完成（报告）

**输入校验**

- 未选文件夹 / 查找词为空 → 对应按钮禁用
- 查找词或替换词含换行符 → 输入框标红并提示
- 查找词与替换词相同 → 提示但允许

**替换后列表**：显示每个文件的处理结果（已替换 N 处 / 失败原因）。

## 8. 错误处理

| 场景 | 行为 |
|---|---|
| 文件被占用 / 无权限 | 跳过该文件，报告中列明 |
| `.docx` 损坏或加密（非有效 ZIP） | 标记错误，不中断整体流程 |
| XML 解析失败 | 跳过该文件并报告 |
| 备份失败 | **中止该文件的替换**（绝不无备份地改动） |
| 备份目录不可写 | 弹窗报错，不执行任何替换 |
| 写入失败 | 保留原文件（atomic 写入保证不会写坏原文件） |
| 目标文件夹无 `.docx` | 提示「未找到 .docx 文件」 |

## 9. 测试策略

### 9.1 纯逻辑单元测试

- **ParagraphMatcher**：跨 run 匹配、大小写开关、全字匹配、同段落多处命中、替换变长/变短/删除、替换词与查找词部分重叠、空段落
- **XmlTextLocator**：`xml:space` 补写、实体转义（`&`/`<`/`>`）、XML 注释与 CDATA 中的伪 `w:t` 干扰、自闭合 `<w:t/>`
- **ZipArchive**：读写往返、stored 与 deflate 两种条目、未改动条目压缩字节逐字节一致、CRC 正确

### 9.2 集成测试

用自研 ZIP 层生成测试夹具 docx（刻意构造：同一词被拆成多个 run、含页眉与文本框、含实体字符、含嵌套段落）。替换后断言：

1. 文字替换结果正确、处数正确
2. **除 `w:t` 文本内容外，整份 XML 完全相同**——"格式不变"的强断言（做法：把两侧 XML 的所有 `w:t` 文本替换为占位符后比较）
3. 输出文件能被系统 `textutil` 正常解析（证明 docx 结构有效）

### 9.3 真实文档端到端验证

用 `textutil` 从真实内容生成 `.docx` 做端到端替换验证，最终由用户在 Microsoft Word 中打开确认格式无损。
